# Product Requirements Document: Neovim Configuration Migration
# NvChad to LazyVim + NvChad UI Components

## 1. Overview

### 1.1 Project Summary
Migrate a personal Neovim configuration fork from a pure NvChad-based setup to the new upstream architecture that uses LazyVim as the foundation with optional NvChad UI components (statusline, tabufline, base46 themes).

### 1.2 Background
The upstream repository (Alexis12119/nvim-config) migrated from pure NvChad to LazyVim + NvChad UI components. This migration provides:
- Better plugin abstractions via LazyVim extras
- Simplified configuration with sensible defaults
- Reduced boilerplate for common plugins
- Maintained access to NvChad's excellent UI components

### 1.3 Goals
1. Update fork to match new upstream LazyVim-based architecture
2. Preserve all personal customizations made in the fork
3. Maintain functionality of custom plugins and keybindings
4. Ensure smooth transition with minimal disruption to workflow

### 1.4 Non-Goals
- Complete rewrite of configuration from scratch
- Removing NvChad UI components (optional - user choice)
- Adding new features not present in current configuration

#### 2.1.6 Key Configuration Pattern Changes

PLUGIN SPEC PATTERN (Old):
```lua
---@type NvPluginSpec
return {
  "plugin/name",
  event = "VeryLazy",
  opts = {},
  config = function(_, opts)
    require("plugin").setup(opts)
  end,
}
```

PLUGIN SPEC PATTERN (New):
```lua
---@type LazySpec
return {
  "plugin/name",
  opts = function(_, opts)
    -- Extend LazyVim defaults
    table.insert(opts.something, value)
  end,
}
```

COLORSCHEME CONDITIONAL LOADING:
```lua
return {
  "plugin/name",
  enabled = vim.g.colorscheme ~= "nvchad",
  -- ...
}
```

LSP CONFIG PATTERN (New):
```lua
return {
  "neovim/nvim-lspconfig",
  opts = {
    servers = {
      lua_ls = {},
      tsserver = {},
    },
  },
}
```

### 4.3 UI Mode Decision

OPTION A: Keep NvChad UI
- Set vim.g.colorscheme = "nvchad" in options
- Keep lua/chadrc.lua configuration
- Statusline customizations (harpoon_indicator, pomo_timer) continue to work
- Use base46 themes including custom eldritch.lua

OPTION B: Use LazyVim Default UI (lualine/bufferline)
- Set vim.g.colorscheme to a standard colorscheme
- Migrate statusline customizations to lualine components
- Use standard theme system
- Simpler long-term maintenance

Recommendation: Start with Option A to minimize initial migration complexity, then optionally migrate to Option B later.

## 6. Risk Assessment

### High Risk
- LSP configuration changes may break language support
- Keybinding conflicts between LazyVim defaults and custom mappings
- Plugin compatibility issues with new lazy.nvim patterns

### Medium Risk
- Statusline customizations may not work with LazyVim UI
- AI plugin configurations may need significant updates
- Some plugins may be deprecated or replaced in LazyVim

### Low Risk
- Filetype detection should work unchanged
- Custom snippets should work unchanged
- Theme files may need minor adjustments

### Mitigation Strategies
1. Test each phase independently before proceeding
2. Keep backup of working configuration
3. Use git branches for easy rollback
4. Document all changes made during migration
5. Test with real projects to verify functionality
